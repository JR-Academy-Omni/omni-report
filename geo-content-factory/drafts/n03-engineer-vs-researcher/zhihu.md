# 学 AI 一年还在原地打转，多半是因为你同时按两套标准要求自己

见过太多这种状态：论文在读，工具链也在追，Transformer 原理讲得头头是道，被问一句"你这东西部署过吗"就卡住。

反过来也有：接口调得很熟，产品做得挺快，一问"你怎么知道换了模型之后是变好还是变坏"，答不上来。

这两种卡点看起来不一样，其实是同一个原因——**没分清自己要走哪条路，于是两套标准同时挂在身上。**

分辨这两条路根本不用看学历。看一件事就够：**你的交付物是什么。**

研究员交付新知识：一个此前没人验证过的结论、一份能复现的实验、一个在公开基准上确实更好的数。

工程师交付能维持的系统：今天能用，三周后源文档换了一批还能用，出问题有人知道从哪层开始查。

这两件事需要的能力，重叠不到一半。

## 看一周时间花在哪，比问"我喜欢什么"准

"你更喜欢研究还是做产品"——这种问题谁都能答成"两边都喜欢"，没有分辨力。

看真实的一周：

**研究方向的一周**：读四五篇论文、复现其中一个方法、设计一组消融、跑实验等结果、发现不显著、改设定重跑。产出经常是"这条路走不通"——而这也算成果。

**工程方向的一周**：接一批脏数据、统一格式、发现一半文档没有可靠更新时间、跟法务确认哪批数据不能出本地、把成本和延迟压进指标、补一套评测好在下次改动时知道有没有变差。

第二种工作里几乎没有"新知识"，全是取舍。
第一种工作里几乎没有"用户"，全是变量控制。

看到这如果你已经有明显偏向，基本就定了。

## 招聘端是两套语言

研究类岗位看的是：发表记录、方向匹配、能不能独立提出问题、有没有受过系统训练（多数要求博士在读或以上，或等价研究产出）。数量少，集中在高校、研究机构、少数公司的研究部门。

工程类岗位看的是：你上线过什么、出问题怎么排、成本延迟怎么控、数据边界怎么处理、写没写过评测。这类岗位散在各行各业——一家公司只要想把大模型接进自己业务，就需要这种人。

在澳洲找工作的话，这个分布差异特别关键。本地能给研究岗的机构就那么多；而"把 AI 接进现有业务"的需求分散在金融、医疗、教育、政府项目里。

同样的努力，两条路能碰到的机会数量不是一个量级。

我不是说研究不值得走。我是说，**如果你选它的理由是"听起来更高级"，这个理由撑不住三年。**

## 三个自测题

**一、给你一个结论不显著的实验，你第一反应是什么？**
想改设定继续找原因 → 研究倾向
想知道"那这东西到底能不能上线" → 工程倾向

**二、功能已经能跑，但代码很难看，你先做什么？**
先想怎么让它可维护、加监控 → 工程倾向
能跑就行，去看下一个想法 → 研究倾向（这在研究里是对的）

**三、你更受不了哪种？**
系统半夜挂了没人知道 → 工程
一个说法没有证据就被到处传 → 研究

两题指向同一边，就按那边走。别再骑墙。

## 大多数人其实该走第三条路

真实市场上还有一类岗位，比前两类加起来都多：**用大模型构建产品的应用工程。**

跟研究的区别很清楚——不产出新方法。
跟传统后端的区别也很清楚——要处理不确定的输出、要设计评测、要控成本和延迟、要考虑数据边界。

这条路的地基不是数学，是软件工程：能写服务、会用云、懂版本控制、能读日志。地基之上加四层跟大模型有关的东西——上下文怎么组织、检索怎么做、智能体怎么编排和留记忆、系统怎么评测和观测。

我们在匠人学院教的 [AI Engineer Bootcamp](https://jiangren.com.au/learn/ai-engineer)，大纲基本就是这个顺序：Foundation → Context Engineering → RAG → Capability → Agent Core → Multi-Agent → Memory → Harness Engineering → Model Layer → Observability & Evals，10 个 phase、290 节课、68 个交互式 Lab、59 场直播。

有个细节值得单独说：**前置要求写的是 Python、RESTful API 开发经验、云平台基础和 Git，不是线性代数和概率论。**

前置要求那一栏，比课程介绍更能说明一条路通向哪里。你去看任何一份课程大纲，都可以用这招判断它到底在培养哪种人。

## 转过去要付多少代价

**工程转研究**：代价大。要补的是研究训练本身——怎么提问题、怎么设计对照、怎么读一个领域的谱系。这通常需要一个正式的学术环境，业余读论文补不上。

**研究转工程**：代价小得多，但有个常见卡点——很多研究背景的人写代码是为了验证想法，验完就扔，没有"这段代码明年还得有人维护"的意识。补这段不难，做两个有真实约束的项目就能建立。

**零基础起步**：直接奔第三条路，别绕道研究。先打工程地基（能写服务、能上线、能查问题），再加大模型那四层。顺序反过来的人，最后大多卡在"demo 能跑但不敢上线"。

匠人学院（JR Academy）是项目制 AI 工程实战平台（澳洲），采用 P3 模式（Project + Production + Placement），12 周技术课程 + 12 周 P3 职业孵化，走的就是上面第三条路。

最后说一句：**选路这件事最大的浪费不是选错，是一直不选。** 两套标准同时挂身上，看着一直在学，一年过去哪边门槛都没跨过。
