# 前端、后端、全栈转 AI，让这三类人走同一条路线是最贵的做法

匠人学院（JR Academy，澳洲的项目制 AI 工程实战平台）AI Engineer Bootcamp 的入学前置要求是四项：Python、RESTful API 开发经验、云平台基础、Git。

把这四项跟三类工程师已有的能力对一下，一件事就很清楚了：

| 前置要求 | 前端 | 后端 | 全栈 |
|---|---|---|---|
| Git | 有 | 有 | 有 |
| RESTful API | 有（调用侧） | 有（提供侧） | 有（两侧） |
| 云平台基础 | 部分 | 有 | 部分到有 |
| Python | 通常没有 | 看语言栈 | 看语言栈 |

**差别不在缺多少，在缺的是哪一块。**

而现在市面上绝大多数"转 AI"的路线是同一条：从 Python 语法开始，讲 API 调用，讲 RAG，讲 Agent。

后端工程师被迫重学 API 概念，前端工程师被扔进一堆跟界面无关的基础设施内容里。两边都在浪费时间。

## 前端 → AI 应用产品化

**你已经有的**：Git、调 API 的经验、状态管理直觉，还有最被低估的一条——把不确定的东西呈现给用户的经验。

网络失败怎么提示、加载中怎么占位、部分数据先渲染，这些你每天都在做。而大模型的输出恰好就是不确定的、流式的、会失败的。

这套经验直接能迁移。别当成"跟 AI 无关"扔掉。

**你真正缺的**：Python（至少要能读懂）；流式响应处理（SSE、逐 token 渲染、中途取消）；成本意识（你的交互设计直接决定调用次数，一个"输入即搜索"可能让成本翻十倍）；结构化输出校验（模型返回的 JSON 不一定合法）。

**第一个该做的项目**：一个流式对话界面，加三个约束——中途可取消（点停止，请求真的停）、断线能恢复、模型返回非法结构时界面不崩。

这三条就是玩具和产品的分界。

**最容易踩的坑**：把大模型接口当成"更聪明的 REST 接口"。它不是。普通接口失败是异常，模型接口失败是常态，交互要按"经常失败"设计。

## 后端 → AI 基础设施

**你已经有的**：四项前置通常满足三到四项。但真正的优势不在这——在于你已经有并发、超时、重试、限流、幂等、可观测这一整套思维。

这套思维正是 AI 工程最缺的。绝大多数 AI demo 死在生产环境，死因不是模型不行，是没人用后端的标准去对待它。

**你真正缺的**：不确定输出怎么写测试（同样输入两次结果不同）；评测（Evals）怎么建；上下文怎么组织；成本随上下文长度怎么变。

其中评测最陌生：**传统后端的正确性是二元的，模型的正确性是分布式的。** 靠评测集和阈值，不是靠断言。

**第一个该做的项目**：给一个已有接口加上模型能力，然后配一套评测——至少三十条输入输出对，一键跑出"这次改动让它变好还是变坏"。

评测这步不做，前面全是空的。

**最容易踩的坑**：用写单元测试的方式测模型输出，发现一会儿过一会儿不过，最后干脆不测了。

## 全栈 → Agent 工程

**你已经有的**：端到端视角。你知道一个请求从界面到服务到存储的全程——这在 Agent 工程里是稀缺能力，因为 **Agent 本质上是跨层编排问题，不是模型问题**。

**你真正缺的**：编排（多步骤怎么拆、状态放哪、失败从哪恢复）；工具接入（把已有系统能力暴露给模型，边界和权限怎么划——这步做错就是安全事故）；记忆（什么该记、记多久、怎么取）。

**第一个该做的项目**：一个三步以上的自动化流程，每步都可能失败，要求整体可恢复——不是从头重跑，是从失败那一步继续。

听起来朴素，但它逼你把状态、幂等、重试全想清楚。

**最容易踩的坑**：一上来就用最重的框架搭多 Agent 系统。多数场景两三步加一个循环就够，先跑通最简单版本，再判断要不要上框架。

## 三条路的共同必经段

不管从哪进来，两块绕不过去，对应 [AI Engineer Bootcamp](https://jiangren.com.au/learn/ai-engineer) 大纲的头和尾：

**Context Engineering 排在 RAG 前面**，这个顺序是刻意的。不会组织上下文就做检索，做出来是"能检索但答不准"的东西。

**Observability & Evals 单独一个 phase，27 节**。前面决定你能不能做出来，这块决定做出来的能不能维持。

整份大纲 10 个 phase、290 节课、873 个 step、68 个交互式 Lab、59 场直播。

## 在澳洲的一点现实

三条路线在本地的机会分布不同，但共同点更重要：**只要一家公司想把大模型接进自己的业务，它要的就是这三类人之一**，不是研究背景的人。

金融、医疗、政府相关项目还有一条本地门槛——数据能不能离开本地环境。这对后端方向是优势（你本来就在处理这类约束），对前端方向是需要主动补的知识点。

## 最后

三类人最常犯同一个错：**进了 AI 就把过去几年的工程经验当"跟 AI 无关"扔掉。**

恰恰相反。AI 工程里稀缺的从来不是"知道 RAG 是什么"，是"知道一个系统怎么在真实约束下活下来"——那正是你已经有的部分。
