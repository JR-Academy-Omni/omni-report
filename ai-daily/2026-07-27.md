## 日报正文

### 1. 【近7天仍在发酵｜模型发布】Claude Opus 5 进入 GitHub Copilot：主打复杂、多步、长程 coding 任务

- 发生了什么：GitHub 于 `2026-07-24` 宣布，`Claude Opus 5` 开始在 `GitHub Copilot` 中逐步上线，覆盖 `VS Code`、`Visual Studio`、`Copilot CLI`、`GitHub Copilot cloud agent`、`github.com`、`GitHub Mobile`、`JetBrains`、`Xcode` 和 `Eclipse` 等入口。
- 为什么重要：这不是单纯多一个模型可选项。GitHub 明确把它定位在复杂、长程、需要多步工具调用和稳定执行的 coding 工作流上，说明前沿模型竞争已经进入“谁更适合真实 agentic 开发任务”的阶段。
- 一句话点评：模型发布的含金量，越来越取决于它能不能第一时间进开发主工作流，而不只是停留在榜单上。
- 来源链接：
  - [GitHub Changelog：Claude Opus 5 is now available in GitHub Copilot](https://github.blog/changelog/2026-07-24-claude-opus-5-is-now-available-in-github-copilot/)

### 2. 【近7天仍在发酵｜Agent 编程】GitHub MCP Server 提前支持下一版 MCP 规范：Stateless 化与并行握手要落地了

- 发生了什么：GitHub 于 `2026-07-23` 宣布，`GitHub MCP Server` 已提前支持下一版 `MCP` 规范。官方明确提到新规范将转向 `stateless core`，移除 `sessions` 和 `initialize`，并让客户端可以并行完成握手；GitHub 也同步移除了 Redis session 依赖并升级了 URL elicitation 兼容逻辑。
- 为什么重要：这不是抽象协议新闻，而是直接影响 Agent 工具生态的底层兼容层。MCP 一旦从“有状态握手”转向更轻的 stateless 设计，远程工具扩展、横向扩容和多客户端接入都会更顺，开发者实际能接的 Agent 工具链也会更稳定。
- 一句话点评：Agent 生态要真跑起来，先得把协议层做成能规模化接、能稳定跑、能快速验证。
- 来源链接：
  - [GitHub Changelog：GitHub MCP Server supports the next MCP specification](https://github.blog/changelog/2026-07-23-github-mcp-server-supports-the-next-mcp-specification/)

### 3. 【近7天仍在发酵｜模型发布】Google 一次放出 Gemini 3.6 Flash、3.5 Flash-Lite 与 3.5 Flash Cyber：Agent 开始分主模型、子模型和安全模型

- 发生了什么：Google 于 `2026-07-21` 发布 `Gemini 3.6 Flash`、`Gemini 3.5 Flash-Lite`，并推出面向 `CodeMender` 的 `Gemini 3.5 Flash Cyber`。官方称 `3.6 Flash` 更偏 coding、知识工作和多模态效率；`3.5 Flash-Lite` 主打高吞吐、低延迟与低成本；`3.5 Flash Cyber` 则面向漏洞发现、验证与修补，并先以有限试点方式向政府和可信伙伴开放。
- 为什么重要：这不是一条模型更新，而是 Google 在公开把 Agent 时代的模型分层讲清楚了: 主模型负责复杂任务，Lite 负责高并发子任务，Cyber 负责安全专项。模型不再只卷“最强单卡”，而是卷“整套工作流里每个角色怎么分工”。
- 一句话点评：接下来真正有竞争力的平台，不是只有一个旗舰模型，而是能不能把主 Agent、子 Agent 和专用 Agent 一起配齐。
- 来源链接：
  - [Google Blog：3.6 Flash, 3.5 Flash-Lite, and 3.5 Flash Cyber](https://blog.google/innovation-and-ai/models-and-research/gemini-models/gemini-3-6-flash-3-5-flash-lite-3-5-flash-cyber/)
  - [Google DeepMind：Introducing Gemini 3.5 Flash Cyber](https://deepmind.google/blog/introducing-gemini-3-5-flash-cyber/)
  - [Gemini API Release Notes：July 21, 2026](https://ai.google.dev/gemini-api/docs/changelog)

### 4. 【近7天仍在发酵｜AI 基建 / 质量】GitHub Code Quality 正式 GA：AI 写得更快后，质量门槛开始商品化

- 发生了什么：GitHub 于 `2026-07-20` 宣布 `GitHub Code Quality` 正式可用，面向 `GitHub Enterprise Cloud` 和 `GitHub Team`。官方强调它把 `CodeQL` 的确定性分析与 `AI-assisted detection`、`Copilot Autofix` 结合起来，并新增组织级启用、质量仪表盘、覆盖率指标和 ruleset 质量门槛。
- 为什么重要：AI 编程工具继续提速后，企业不会只买“写代码更快”，还要买“写快了之后怎么控可靠性和可维护性”。Code Quality 从预览变成付费产品，说明“AI 时代的软件质量治理”已经进入正式采购和预算阶段。
- 一句话点评：AI 把代码产量拉高后，下一个会变成标准件的，就是质量与修复闭环。
- 来源链接：
  - [GitHub Changelog：GitHub Code Quality is now generally available](https://github.blog/changelog/2026-07-20-github-code-quality-is-now-generally-available/)

### 5. 【近7天仍在发酵｜产品更新】Copilot 用户现在能直接看到本账期 AI credits：企业开始把 AI 使用量做成人人可见

- 发生了什么：GitHub 于 `2026-07-20` 更新 `Copilot usage page`，让 `Copilot Business` 和 `Copilot Enterprise` 用户即使没有个人预算，也能直接查看本账期已经消耗的 `AI credits`；如果管理员设置了预算，页面则会显示“已用额度 / 总预算”。
- 为什么重要：预算和成本可见性看起来不如新模型吸睛，但它决定了 AI 工具能不能从试点走向常态化采购。只有个人、团队和管理员都能看见实际消耗，企业才有条件把用量管理、预算分配和 AI 采购 ROI 做细。
- 一句话点评：企业级 AI 的成熟标志之一，不是更会 demo，而是每个人都能看见这月到底花了多少。
- 来源链接：
  - [GitHub Changelog：Copilot users can now see AI credits used per billing cycle](https://github.blog/changelog/2026-07-20-copilot-users-can-now-see-ai-credits-used-per-billing-cycle/)
