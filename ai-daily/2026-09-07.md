## 日报正文

### 1. 【模型发布｜2026-09-02】Meta 发布 Muse Spark 1.3，强化长链路 Agent 与编程任务

- 发生了什么：Meta 于 `2026-09-02` 发布 `Muse Spark 1.3`，并在 `Muse Code` 与 `Meta Model API` 提供最高推理档位。官方称，新版重点提升长时程 Agent、工具调用、多任务上下文保持和复杂指令遵循；模型可在信息冲突、目标开放的任务中自行补足上下文并修正计划。
- 为什么重要：它把竞争从“单次回答更强”拉到“能否持续做完复杂任务”。这正是 Agent 编程、研究和自动化工作流最需要的能力层。
- 一句话点评：Agent 的分水岭不是会不会调工具，而是任务拉长后还能不能稳住目标。
- 来源：[Meta AI Research：Introducing Muse Spark 1.3](https://research.meta.ai/blog/introducing-muse-spark-1-3)

### 2. 【多模态能力｜2026-09-03】微软发布 MAI-Transcribe-2，覆盖 60 种语言并加入说话人分离

- 发生了什么：Microsoft 于 `2026-09-03` 上线自研语音转文字模型 `MAI-Transcribe-2`，已在 `Azure Speech` 公共预览。模型支持 `60` 种语言自动识别，新增说话人分离、逐词时间戳和领域关键词偏置；微软给出的限时价格为 `0.10 美元 / 小时音频`，截至 `2026-12-31`。
- 为什么重要：高质量转写正在从“把音频变文字”升级为可直接服务会议纪要、客服质检、无障碍字幕和语音 Agent 的结构化数据入口。
- 一句话点评：语音模型的价值不只在听清，更在能不能把多人、时间和行业术语一起交付。
- 来源：[Microsoft Foundry：MAI-Transcribe-2 模型目录](https://ai.azure.com/catalog/models/MAI-Transcribe-2)；[Microsoft Community Hub：MAI-Transcribe-2](https://techcommunity.microsoft.com/blog/azure-ai-foundry-blog/mai-transcribe-2-highest-quality-transcription-at-the-fastest-speed-and-lowest-c/4550972)

### 3. 【Agent 编程｜后续进展｜2026-09-04】GPT-6 Astra 现已在 GitHub Copilot 中可选

- 发生了什么：在 `2026-09-03` 宣布滚动开放后，GitHub 于 `2026-09-04` 宣布 `GPT-6 Astra` 已在 `GitHub Copilot` 可用，覆盖 `VS Code`、`Visual Studio`、`Copilot CLI`、编码 Agent、Copilot 应用、GitHub 网页与移动端，以及 JetBrains、Xcode、Eclipse。适用方案包括 `Pro+`、`Max`、`Business`、`Enterprise`，按模型的用量计费。
- 为什么重要：这是此前“模型发布”的明确后续进展：前沿模型直接进入覆盖面最广的开发者 Agent 入口，模型能力开始转换为日常开发工具选择。
- 一句话点评：模型一旦进 Copilot，真正的竞争才从发布会进入开发者的默认工作流。
- 来源：[GitHub Changelog：GPT-6 Astra is generally available in GitHub Copilot](https://github.blog/changelog/2026-09-04-gpt-6-astra-is-generally-available-in-github-copilot/)

### 4. 【Agent 编程｜2026-09-04】GitHub 预览 HydraFusion，在运行时编排多个模型完成编码任务

- 发生了什么：GitHub 于 `2026-09-04` 发布研究预览 `Project HydraFusion`。它会先生成完整执行计划，再从多个供应商的模型中选择模型进行起草、批评、修订，或在需要时升级到更强模型；GitHub 称其在 `TerminalBench 2.1`、`DeepSWE` 和内部 `CheckpointBench` 的离线评估中，以更低的预估工作流成本达到或超过所评估 `Claude Opus 5` 基线。
- 为什么重要：这让“选哪个模型”从人工下拉菜单，变成系统按任务阶段调度的运行时能力；对长链路编码任务，成本和验证环节比单次 benchmark 更关键。
- 一句话点评：下一代 Copilot 可能不是一个模型，而是一支会分工、会复核的模型小队。
- 来源：[GitHub Blog：Project HydraFusion: Frontier quality via multi-model orchestration](https://github.blog/ai-and-ml/github-copilot/project-hydrafusion-frontier-quality-via-multi-model-orchestration/)

### 5. 【产品更新｜2026-09-04】Google 将 Lyria 3.5 扩至 Gemini 应用与 Gemini API

- 发生了什么：Google 于 `2026-09-04` 将音乐生成模型 `Lyria 3.5` 从此前的 `Flow Music` 扩展到 `Gemini` 应用、`Gemini API`、`Google AI Studio` 与 `Google Vids`。开发者模型 ID 为 `lyria-3.5`，可从文本或图片生成完整歌曲，支持 `44.1 kHz` 立体声音频和带主歌、副歌、桥段的数分钟结构；生成结果带 `SynthID` 水印。
- 为什么重要：这不是全新基础模型，而是一次重要的产品化扩容：音乐生成从垂直创作工具走进通用助手与 API，意味着它更容易被接入营销、视频和内容产品工作流。
- 一句话点评：生成式音乐要真正普及，关键不是多一个网页入口，而是能不能成为任意产品里的能力模块。
- 来源：[Google Gemini API：Music generation](https://ai.google.dev/gemini-api/docs/music-generation)；[Google AI Studio 官方公告（2026-09-04）](https://x.com/GoogleAIStudio/status/1963635041168892108)
