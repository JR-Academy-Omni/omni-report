## 日报正文

### 1. 【近2天主线｜产品更新】GitHub 给 Copilot app 单独加策略开关：企业可独立控制谁能用桌面端 Agent

- 发生了什么：GitHub 于 `2026-07-27` 发布 `Manage GitHub Copilot app access with a dedicated policy`。`Copilot app` 不再依赖 `Copilot CLI` 策略联动开启，而是拥有独立的企业 / 组织级访问策略，管理员可选 `Enabled everywhere`、`Disabled everywhere` 或 `Let organizations decide`。
- 为什么重要：这不是简单加个后台开关，而是把 Copilot app 从附属入口变成可被正式纳管的独立客户端。企业要想大规模放开桌面 Agent，第一步就是能精确决定哪些团队、哪些表面可以用。
- 一句话点评：AI 工具真正进组织，不是先卷功能，而是先把“谁能开、谁不能开”说清楚。
- 来源链接：
  - [GitHub Changelog：Manage GitHub Copilot app access with a dedicated policy](https://github.blog/changelog/2026-07-27-manage-github-copilot-app-access-with-a-dedicated-policy/)

### 2. 【近2天主线｜Agent 编程】Enterprise managed settings 扩到 Copilot app 和 cloud agent：插件、审批、模型默认值开始统一管

- 发生了什么：GitHub 于 `2026-07-27` 发布 `Enterprise managed settings in the GitHub Copilot app and Copilot cloud agent`。企业可用同一份 `managed-settings.json` 统一控制 `Copilot app` 与 `Copilot cloud agent` 的插件可用性、marketplace 来源、是否可绕过审批提示，以及新对话默认自动选模型等策略。
- 为什么重要：AI coding 从 IDE 延伸到 app 和异步 cloud agent 后，治理面不能继续碎片化。现在企业能把插件、审批和默认模型选择跨客户端统一落地，说明 GitHub 正在补“同一套 guardrails 覆盖全部表面”的关键能力。
- 一句话点评：企业真正怕的从来不是员工不用 AI，而是不同入口各自失控。
- 来源链接：
  - [GitHub Changelog：Enterprise managed settings in the GitHub Copilot app and Copilot cloud agent](https://github.blog/changelog/2026-07-27-enterprise-managed-settings-now-apply-to-the-github-copilot-app/)

### 3. 【近7天仍在发酵｜模型发布】Gemini 3.6 Flash 进入 GitHub Copilot：主打长程 Agent 任务与并行工具调用

- 发生了什么：GitHub 于 `2026-07-21` 宣布 `Gemini 3.6 Flash` 开始在 `GitHub Copilot` 中逐步上线，覆盖 `VS Code`、`Visual Studio`、`Copilot CLI`、`cloud agent`、`GitHub Copilot app`、`JetBrains`、`Xcode` 和 `Eclipse` 等入口。官方强调它支持 `configurable reasoning effort` 和复杂工作流中的 `parallel tool use`。
- 为什么重要：这不是单纯再多一个模型选项，而是 GitHub 持续把前沿模型直接塞进开发主工作流里，并把“长程任务 + 并行工具调用”作为明确卖点。模型竞争已经越来越像“谁更适合真实 Agent 工作流”。
- 一句话点评：前沿模型有没有价值，越来越取决于它能不能第一时间进入默认开发入口。
- 来源链接：
  - [GitHub Changelog：Gemini 3.6 Flash is now available in GitHub Copilot](https://github.blog/changelog/2026-07-21-gemini-3-6-flash-is-now-available-in-github-copilot/)

### 4. 【近7天仍在发酵｜企业落地】GitHub 上线 Copilot impact dashboard：从活跃人数转向看 adoption phase 与产出差异

- 发生了什么：GitHub 于 `2026-07-22` 发布 `New Copilot usage metrics impact dashboard`。面向企业管理员和组织 owner 的新看板会按 `AI adoption phase` 分组展示用户状态，并给出每阶段的 `PR merged per user per month`、`median merge velocity`、用户占比、`lines of code per day per user` 以及趋势图和下一步建议。
- 为什么重要：企业不再只满足于“买了多少 license、多少人打开过”。这个面板开始把 AI 采用深度、PR 速度与吞吐变化直观看出来，等于把“Copilot 到底有没有产出”做成了管理层可读的产品能力。
- 一句话点评：AI 进入预算周期后，活跃人数不是终点，能不能讲清楚产出差异才是。
- 来源链接：
  - [GitHub Changelog：New Copilot usage metrics impact dashboard](https://github.blog/changelog/2026-07-22-new-copilot-usage-metrics-impact-dashboard/)

### 5. 【近7天仍在发酵｜AI 基建 / 成本】AI credit pools 进 GitHub billing UI：成本中心终于能直接控包含额度

- 发生了什么：GitHub 于 `2026-07-20` 更新 `AI credit pools for cost centers in the billing UI`。`Copilot Business` 与 `Copilot Enterprise` 用户现在可直接在 billing UI 为 cost center 打开 `AI credit pool`，由系统按分配 license 自动计算额度，并可设置到上限后阻断继续使用或允许按额外支出继续。
- 为什么重要：这把“AI 用量预算”从 API 管理功能推进成了可直接配置的产品能力。对大团队来说，这种成本中心级的额度池，是把 AI 编程从试点工具做成正式 IT 预算项的重要一步。
- 一句话点评：企业敢把 AI 真正铺开，前提往往不是模型更强，而是账先能管住。
- 来源链接：
  - [GitHub Changelog：AI credit pools for cost centers in the billing UI](https://github.blog/changelog/2026-07-20-ai-credit-pools-for-cost-centers-in-the-billing-ui/)
