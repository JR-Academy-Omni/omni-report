## 日报正文

### 1. 【近3天主线｜Agent 编程】GitHub Copilot for JetBrains 大更新：补 OpenTelemetry、模型治理、MCP 与自定义 agent

- 发生了什么：GitHub 于 `2026-07-27` 发布 `GitHub Copilot for JetBrains adds improved OpenTelemetry configuration and model management`。新版本支持为 agent workflows 配置 `OpenTelemetry export`，为 `BYOK` 和自定义 endpoint 设置默认 `maxInputToken` / `maxOutputToken`，并可在 `Claude agent flows` 中直接使用 `MCP servers` 与 `custom agents`。
- 为什么重要：这不是普通 IDE 插件打补丁，而是在把企业真正在意的可观测性、模型控制和工具扩展补进主开发入口。JetBrains 用户终于不只是“能用 Copilot”，而是开始能把它纳入团队治理和自定义工作流。
- 一句话点评：Agent 真要进企业开发主流程，先得把遥测、模型边界和工具接入做成可管理系统。
- 来源链接：
  - [GitHub Changelog：GitHub Copilot for JetBrains adds improved OpenTelemetry configuration and model management](https://github.blog/changelog/2026-07-27-github-copilot-for-jetbrains-adds-improvved-opentelemetry-configuration-and-model-management/)

### 2. 【近3天主线｜产品更新】GitHub 给 Copilot app 单独加策略：桌面端入口正式进入企业权限体系

- 发生了什么：GitHub 于 `2026-07-27` 发布 `Manage GitHub Copilot app access with a dedicated policy`。`Copilot app` 不再依赖 `Copilot CLI` 的联动策略，而是拥有独立的企业 / 组织级访问控制，管理员可设为 `Enabled everywhere`、`Disabled everywhere` 或 `Let organizations decide`。
- 为什么重要：这意味着 Copilot app 不再只是新客户端，而是进入了企业正式的权限与放行体系。对准备推广桌面端 Agent 的团队来说，先能独立控入口，后面才谈得上规模铺开。
- 一句话点评：AI 客户端一旦进入企业，就必须先像正式软件一样被单独纳管。
- 来源链接：
  - [GitHub Changelog：Manage GitHub Copilot app access with a dedicated policy](https://github.blog/changelog/2026-07-27-manage-github-copilot-app-access-with-a-dedicated-policy/)

### 3. 【近3天主线｜Agent 编程】Enterprise managed settings 扩到 Copilot app 和 cloud agent：多入口开始共用一套 guardrails

- 发生了什么：GitHub 于 `2026-07-27` 发布 `Enterprise managed settings in the GitHub Copilot app and Copilot cloud agent`。企业现在可用同一份 `managed-settings.json` 统一控制 `Copilot app` 和 `Copilot cloud agent` 的插件来源、审批绕过、模型默认值等策略。
- 为什么重要：这解决的是“AI 入口越来越多，但治理越来越碎”的问题。只要 app 和 cloud agent 共用同一套策略，企业才有可能把多入口 Copilot 真正当成一套系统，而不是一堆各管各的实验功能。
- 一句话点评：Copilot 从工具变系统，关键一步就是不同入口终于开始共享同一套治理边界。
- 来源链接：
  - [GitHub Changelog：Enterprise managed settings in the GitHub Copilot app and Copilot cloud agent](https://github.blog/changelog/2026-07-27-enterprise-managed-settings-now-apply-to-the-github-copilot-app/)

### 4. 【近7天仍在发酵｜Agent 自动化】GitHub Issues 上线 agent automation controls：审批、置信度和理由开始标准化

- 发生了什么：GitHub 于 `2026-07-23` 发布 `Agent automation controls in GitHub Issues in public preview`。新能力包括 `approvals`、`confidence` 和 `rationale`，让 Agent 对 labels、fields、type、close、assignees 等动作可先给建议、附置信度与理由，再决定是否自动应用。
- 为什么重要：这直接回答了企业最现实的问题: Agent 自动化可以跑，但出了手你怎么审、怎么追责、怎么定自动化强度。GitHub 把这些治理能力产品化后，Issue 自动化才更像能落地的企业功能。
- 一句话点评：Agent 能不能大规模放出来跑，分水岭不在“会不会做”，而在“你敢不敢让它自动做”。
- 来源链接：
  - [GitHub Changelog：Agent automation controls in GitHub Issues in public preview](https://github.blog/changelog/2026-07-23-agent-automation-controls-in-github-issues-in-public-preview/)

### 5. 【近7天仍在发酵｜Agent 编程】Copilot cloud agent for Linear GA：异步接单、开草稿 PR、评论里继续 steer

- 发生了什么：GitHub 于 `2026-07-23` 发布 `Copilot cloud agent for Linear is now generally available`。把 `Linear issue` 指派给 Copilot 后，它会在临时开发环境里异步工作、开 `draft pull request`，并把进度写回 `Linear`；同时你还能按 issue 选择模型、自定义 agent、base / working branch，并在评论里继续给新指令。
- 为什么重要：这不是简单多一个插件，而是把“需求管理 → 异步执行 → PR 交付 → 评论继续 steer”串成了完整链路。开发 Agent 正在从 IDE 内的助手，变成能在项目系统里接工单的协作者。
- 一句话点评：当 Agent 能在 Linear 里直接接单和回报进度，研发协作入口就开始被重新定义了。
- 来源链接：
  - [GitHub Changelog：Copilot cloud agent for Linear is now generally available](https://github.blog/changelog/2026-07-23-copilot-cloud-agent-for-linear-is-now-generally-available/)
