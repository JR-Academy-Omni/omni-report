# AI 日报自动化执行规范

> 适用对象：`每日 AI 日报 Top 5` 自动化
> 生效目标：避免每天按错口径、漏掉中文市场高传播条目、海报与正文脱节

## 1. 固定口径

- 定时任务默认在**每天早上 8:00（北京时间）**执行。
- 每天 8:00 这次运行必须同时产出：
  - 当天 `ai-daily/YYYY-MM-DD.md`
  - 当天海报图片成品
- 默认按**中文传播场**做选题，不按“纯英文媒体 / 纯海外大厂发布榜”做。
- 默认回看**近 3 天**，但不是机械只看当天。
- 默认目标是 **Top 5**。
- 只有在**严格核验后仍明显不足 5 条**时，才允许少于 5 条；否则不要做成 Top 1 / Top 3。

## 2. 优先级

优先级固定如下：

1. 模型发布 / 模型升级 / 版本切换
2. 大产品上线 / 大产品更新 / 功能入口级变化
3. Agent / 编程工具 / 开发者工作流产品
4. 多模态能力发布
5. AI 基建 / 芯片 / 推理成本 / 模型迁移窗口
6. 中文市场高传播监管 / 会展 / 平台动作

补充规则：

- 对中文市场日报，**国内监管、WAIC/大型会展前瞻、国内开发者工具更新**不能默认降权到看不见。
- 政策、监管、会展类原本可降权，但如果它已经成为**中文传播场当天主线**，必须纳入候选。

## 3. 去重规则

- 必须回看最近 3 天已发布的 `ai-daily/YYYY-MM-DD.md`。
- 同一事件如果前几天已经上过，默认不重复。
- 但如果出现**新的明确进展**，允许再次上榜，并在标题或正文里标注“后续进展”。
- 如果用户明确要求**不少于 5 条**，则可补入“近 7 天仍在发酵”的高优先级条目，但必须写明这是补入项，不能伪装成当天新发布。

## 4. 必选来源类型

- 优先官方文档、官方公告、官方 changelog、官方大会页、可信媒体。
- 中文市场条目可使用中文媒体，但必须尽量搭配更硬的来源：
  - 官方法规页
  - 官方大会官网
  - 官方 API 文档
  - 官方 changelog / 产品页
- 不可只靠二手转述、纯公关稿、无法验证的社媒截图。

## 5. 2026-07-14 后新增的硬规则

以下是用户明确追加、必须长期记住的要求：

- 默认以**中文市场今天真正会传播的 5 条**为目标。
- 正文默认**不少于 5 条**。
- 候选必须覆盖以下类型，只要当天有传播价值就不能漏：
  - 中国监管 / 合规落地
  - WAIC 等国内 AI 大会前瞻
  - 国内模型迁移 / API 变更 / 开发者生态更新
  - Meta / OpenAI / Anthropic 等平台级产品入口变化
  - Cursor / Claude Code / 类 Cursor 工具的移动端、Agent、PR 工作流更新
- 不能因为“前几天写过海外条目”就把中文市场当天真正会传播的内容全部筛掉。

## 5.1 2026-07-15 后新增的选题裁决规则

以下规则用于解决“内容看起来热，但不适合日报主榜”的问题：

### A. 排名先看事件类型，不先看话题热度

- 能排进前 3 的，优先必须是：
  - 新模型发布 / 升级 / 版本切换
  - 产品入口级更新
  - 开发者工作流变化
  - 明确融资 / 估值 / 数据中心 / 芯片 / API 迁移窗口
- 单纯“高管呼吁监管”“采访观点”“趋势评论”“个人实验故事”，默认**不能进入前 2**。

### B. 政策 / 监管只在“直接改产品”时上榜

- 只有同时满足以下任一条件，政策 / 监管类才可入榜：
  - 已经生效，并导致产品功能下线 / 收口 / 调整
  - 明确改变模型发布节奏、出口边界、可售区域、审查流程
  - 已有具体日期、机构、执行范围，而非泛泛倡议
- 纯“建议成立机构”“呼吁加强监管”一类，除非当天没有更强产品 / 模型 / 商业化事件，否则不进主榜。

### C. 融资新闻默认降权，但满足 3 条可升权

- 融资 / 估值 / IPO / 配股新闻，只有当下面 3 条至少满足 2 条时，才值得进主榜：
  - 金额或估值足够大，足以影响行业认知
  - 明确绑定算力、数据中心、芯片、自研基础设施、模型商用化
  - 为近 3 天内的新进展，而不是旧融资回顾

### D. 不把“软故事”排在“硬变化”前面

- 以下类型默认只能做补位项，不应压过真实产品与模型变化：
  - 个人使用 AI 的故事
  - 观点型专访
  - 没有官方页 / changelog / 财务动作支撑的媒体 feature

### E. 若存在多套候选，以“最可验证的一套”为准

- 当天若出现截图版、草稿版、旧海报版和正文版不一致：
  - 不追随更吸睛的版本
  - 以**来源最硬、时间最新、最符合优先级**的一套为准
  - 必须同步重写正文、海报和 memory，避免“图一版、文一版”

## 5.2 2026-07-27 后锁定的日报成品格式

以下为用户确认后固定沿用的成品规则，后续每天早上 `08:00`（北京时间）自动运行时默认照此执行：

### A. 正文结构锁定

- 标题固定为：`# AI 日报 · TOP 5 · YYYY-MM-DD`
- 开头第一段必须交代：
  - 执行日期
  - 默认先回看近 3 天
  - 与最近 3 期日报去重
  - 如果近 3 天硬新闻不足，要明确写出补入了“近 4-7 天仍在发酵”条目
- 正文每条固定包含：
  - `发生了什么`
  - `为什么重要`
  - `一句话点评`
  - `来源链接`

### B. 口径表达锁定

- 如果条目并不在严格近 3 天窗口内，绝不能写成“近 3 天主线”。
- 允许使用的诚实标注包括：
  - `近4天仍在发酵`
  - `近5天仍在发酵`
  - `近7天仍在发酵`
  - `后续进展`
- 若严格近 3 天不足 3 条：
  - 可以补入近 7 天高价值条目
  - 但必须在开头段落和“说明”区明确交代
  - 不得伪装成当天新发布

### C. 风格锁定（以 2026-07-24 确认版为准）

- 不写成泛泛“行业观察”或“观点盘点”。
- 要尽量像 `2026-07-24` 这版：
  - 先给一句清晰主线判断
  - 优先选择模型发布 / 大产品更新 / Agent 工作流 / AI 基建硬动作
  - 每条都落到具体产品、版本、入口、金额、部署节点或明确功能动作
- 不要把纯公关口号直接改写成日报标题；必须落到可验证功能。

### D. 海报文案锁定

- 海报主标题继续保持：
  - `AI 日报`
  - `AI 新闻榜`
  这一类风格，不另起奇怪栏目名。
- 海报的 `hero.headline` 和 `hero.highlight` 必须与正文主线一致。
- 海报卡片标题要尽量具体，优先写功能动作，不写空泛判断。

### D.1 海报版式锁定

- 默认母版以用户确认的 `2026-07-29` 高密度新闻海报为准，不允许退回极简列表版。
- 画布尺寸锁定为 `1024 × 1536`（2:3 竖版）。不要再使用 `1054 × 1492`、`979 × 1318` 或其他旧尺寸。
- 必须保留这些结构：
  - 顶部品牌栏
  - 右上日期 pill
  - hero 顶部红色 `今日主线` 标签
  - 左侧超大主线标题区（标题写当天判断，不写大日期）
  - 主线标题下方直接放带红色竖线的补充说明区
  - 右侧牛小匠主视觉
  - 底部 5 条浅色渐变新闻卡片
  - 每条卡片右侧的同色系线性插画图标组
- hero 禁止回退到“大日期 + AI 新闻榜 + 今日 5 条”的旧结构；`7月X日` 只能出现在右上日期 pill 或正文文件名里，不能作为 hero 主视觉。
- 不要再使用“只有大日期 + 简单列表 + 小图标块”的简化版，也不要使用实心色块图标卡。
- 如果当日内容需要压缩，优先压缩文案字数，不要删掉上述结构层。
- hero 中不要再放一整段新闻摘要；大标题已经负责信息密度，摘要会让首屏显得太挤。
- 卡片标题必须先压成海报短标题，确保没有孤字断行、英文单词硬拆、文字撞到右侧图标组或 footer。

### D.2 牛小匠使用规则

- 牛小匠是 AI 日报海报的必备品牌角色，每张成品海报都必须出现。
- 牛小匠必须使用品牌库官方素材池或 image model 基于品牌形象生成的同风格变体，不可换成其他角色或无品牌感手绘替代。
- 牛小匠不能每天机械复用同一张、同一姿势、同一表情；必须根据当天主线内容切换形象、动作、道具和站位：
  - 编程 / Agent / 开发者工具：优先 coding / laptop 类
  - 产品发布 / 平台更新：优先 laptop / pointing / thinking 类
  - 数据 / 企业治理 / dashboard：优先 teaching / chart / clipboard 类
  - 机器人 / 物理世界：优先 robot / lab / controller / tablet 类
  - 安全 / 治理：优先 shield / alert / checklist / monitor 类
  - 庆祝类重大发布：可用 cheering / celebration 类
- 如果没有特别匹配的官方姿势，再退回通用全身站姿。
- 自动化每天出海报时，必须先判断当天主题，再选最匹配的牛小匠形象；连续两天不得使用完全相同的牛小匠姿势和道具组合。

### D.3 右侧插画图标区规则

- 底部 5 条新闻卡片右侧的插画图标区，也必须根据该条新闻的具体内容单独设计，不能直接照搬上一期或复用固定模板。
- 规则是“前面写什么，右边就画什么”：
  - 策略 / 开关 / 权限：画开关、控制台、权限面板、机器人等
  - 云端 / 配置 / managed settings：画云、连接线、配置面板、齿轮等
  - 模型速度 / Flash / 推理：画闪电、速度线、模型徽章等
  - dashboard / 指标 / impact：画图表、柱状图、仪表盘、趋势指针等
  - billing / credits / cost pool：画账单、数据库、金额、额度环、百分比等
- 允许沿用统一的圆角浅色底卡风格，但图标内容本身必须和该条新闻语义匹配。
- 不允许出现“文案换了，但右侧图还是上一期那套语义”的情况。

### E. 图文一致性锁定

- 如果正文改了条目标题、来源口径或功能描述：
  - 海报必须同步重出
  - memory 必须同步更新
  - 不能出现正文已修正、海报仍是旧文案的情况

### F. 海报交付前自检

每次交付前必须人工目检成品 PNG，至少确认：

- 图片尺寸是 `1024 × 1536`。
- hero 是 `今日主线 + 大号主线标题 + 摘要 + 红竖线点评`，不是“大日期 + AI 新闻榜”。
- 5 条卡片全部完整露出，footer 不压卡片。
- 卡片标题没有孤字断行、英文单词硬拆、文字和右侧图标重叠。
- 右侧牛小匠没有被裁切，也没有被额外 UI / 气泡 / 数据框污染。

## 6. 海报规则

- 每次都要生成**真正的海报图片文件**，不能只交 SVG 草稿。
- 海报必须使用 **image model 直接生成**，不能使用 HTML 截图、脚本排版截图或程序化拼图冒充成品。
- 海报必须和正文条数一致：
  - 正文 Top 5，海报也必须是 Top 5
  - 正文 Top 3，海报也必须是 Top 3
- 吉祥物牛小匠必须出现，但每天要按主题变化姿势 / 道具 / 表情，不能固定复用同一张：
  - `jr-academy-brand/assets/mascot/official/01-hero-fullbody.png`
- 视觉固定沿用当前确认版式：
  - 白底圆角卡片
  - 顶部品牌栏
  - 主标题保持“AI 日报 / AI 新闻榜”风格
  - 右侧保留吉祥物
  - 条数信息只做副信息，不抢主视觉
  - 紧凑版，不做超长图
  - 版心、比例、安全区沿用 `2026-07-24` 确认母版

## 7. 落盘与发布

- 正文只写入：`omni-report/ai-daily/YYYY-MM-DD.md`
- 不要改 `curriculum/`
- 做完后默认执行：
  - 子库内 `git add` 本次文件
  - `git commit`
  - `git push origin HEAD:main`
  - 回主仓库更新 submodule 指针并 `pull --rebase` 后推送

## 8. 自动化记忆要求

- 每次运行后都要把当日执行结论写入：
  - `/Users/chengduyuanqizhishukejiyouxiangongsi/.codex/automations/ai-top-5/memory.md`
- memory 至少记录：
  - 当天最终条数
  - 用的是哪套口径
  - 有没有补入“近 7 天仍在发酵”条目
  - 有没有因用户新增规则而调整执行方式

## 9. 失败时的处理

- 如果发现选题口径明显跑偏，不要只补一句解释。
- 必须同时修正：
  - 正文
  - 海报
  - memory
  - git 发布状态
